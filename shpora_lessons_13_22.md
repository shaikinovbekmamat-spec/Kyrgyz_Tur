## Подготовка к демонстрации

Из корня проекта, при запущенном PostgreSQL и заполненном `.env`:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

Создание суперпользователя нужно только при отсутствии подходящей учётной записи. Адрес сайта: http://127.0.0.1:8000/, админки: http://127.0.0.1:8000/admin/. В админке подготовьте регион, категорию, активный тур и будущую дату со свободными местами. Для демонстрационных данных есть команда `manage.py seed_demo`; она не заменяет требование самостоятельно добавить записи через админку.

## Урок 13: Структура Web приложения

**Статус: реализована структура продукта; описание моделей дополнено ниже.** Задание разрешает свой продукт, блог указан только как вариант по умолчанию. Здесь продукт — сайт туров по Кыргызстану.

**Что сделано:**

- `Kyrgyz_Tur/` содержит настройки, корневые URL, WSGI и ASGI. `manage.py` запускает команды проекта.
- `tours/` содержит каталог, поиск, фильтры, карточки и подбор туров, отзывы; `bookings/` — бронирования и профиль.
- `users/views.py` содержит регистрацию. Это модуль с представлением, а не подключённое в `INSTALLED_APPS` самостоятельное приложение: в настройках зарегистрированы `tours` и `bookings`.
- `Kyrgyz_Tur/urls.py` связывает `/`, `/tours/`, `/bookings/`, `/accounts/` и `/admin/`. Шаблоны лежат в общем `templates/` и каталогах приложений.

**Структура моделей и полный список объявленных полей** (у моделей дополнительно есть автоматический первичный ключ `id`; точные типы и ограничения находятся в `tours/models.py` и `bookings/models.py`):

| Модель | Назначение и поля |
| --- | --- |
| `Region` | Регион: `name`, `description` |
| `TourCategory` | Категория: `name` |
| `Tour` | Тур: `name`, `slug`, `description`, `region`, `category`, `duration_days`, `difficulty`, `price`, `route`, `included`, `not_included`, `max_participants`, `is_active`, `created_at`, `updated_at` |
| `TourImage` | Фотография: `tour`, `image`, `caption`, `is_main`, `order` |
| `TourDate` | Дата поездки: `tour`, `date`, `end_date`, `available_spots`, `price_modifier` |
| `Review` | Отзыв: `tour`, `user`, `rating`, `comment`, `created_at` |
| `Booking` | Заявка: `user`, `tour`, `tour_date`, `participants_count`, `total_price`, `status`, `contact_name`, `contact_phone`, `contact_email`, `special_requests`, `created_at`, `updated_at`, `confirmed_at` |
| `UserProfile` | Профиль: `user`, `phone`, `date_of_birth`, `preferred_budget_min`, `preferred_budget_max`, `preferred_duration_days`, `interests`, `created_at` |

Пользователь — встроенная модель Django `User`. Регион и категория связаны с турами через `ForeignKey`; тур связан с фотографиями, датами, отзывами и заявками. Профиль связан с пользователем через `OneToOneField`.

**Что осталось:** дополнительных частей структуры из условия не обнаружено. На защите нужно объяснить связи и разделение ответственности.

**Как показать через интерфейс:** открыть главную, каталог, карточку тура, после входа — бронирования и профиль. Архитектуру каталогов и связи моделей браузер непосредственно не показывает: открыть дерево проекта, `urls.py` и файлы моделей в IDE.

## Урок 14: Работа с базами данных, ORM

**Статус: основная часть сделана; учебный эксперимент с миграциями и ручное заполнение не подтверждены.**

**Что сделано:** восемь собственных моделей перечислены в уроке 13. Используются строки, текст, даты, изображения, денежные `DecimalField`, числовые и логические поля, внешние ключи и связь один к одному. Для каждого класса определён `__str__` — соответствующий способ строкового представления в Python 3 вместо указанного в старом задании `__unicode__`. Есть вычисление цены даты, выбор доступных дат, подтверждение и отмена бронирования. Все восемь моделей зарегистрированы в `tours/admin.py` и `bookings/admin.py`.

В обоих приложениях есть миграции `0001_initial.py` и `0002_...`: создание структуры и изменение полей/ограничений. Наличие файлов миграций не доказывает, что они применены к рабочей базе.

**Что осталось:** в имеющихся миграциях нет учебной последовательности «удалить поле → создать миграцию → вернуть поле → создать миграцию». При необходимости выполнить её на отдельной учебной базе, чтобы не потерять данные. Добавление нескольких записей именно через админку нужно показать отдельно; наличие `seed_demo` этого не доказывает. Применение миграций проверяется командой `manage.py showmigrations`.

**Как показать через интерфейс:** в `/admin/` создать регион, категорию и несколько туров, в туре добавить дату и фотографию, сохранить, затем показать их в каталоге. Отображаемые названия объектов демонстрируют `__str__`. Сам ORM и историю миграций через интерфейс сайта показать нельзя — открыть модели и миграции в IDE, выполнить `showmigrations` в терминале.

## Урок 16: Forms — комментарии

**Статус: частично. Наличие форм бронирования не закрывает конкретное задание о комментариях.**

**Что сделано по заданию:** аналог комментария — `Review`. В `tours/views.py:add_review` есть обработка POST: проверяется оценка 1–5, непустой текст после `strip()`, завершённая поездка пользователя и отсутствие повторного отзыва на тот же тур. Созданный отзыв сохраняется и выводится в `tour_detail.html`; средняя оценка вычисляется представлением. Маршрут обработчика: `/tours/<slug>/review/`.

**Что осталось:**

- На странице тура нет HTML-формы отправки отзыва. Поэтому обычный пользователь пока не может отправить его через интерфейс сайта, хотя обработчик существует.
- Нет отдельной темы комментария и проверки её обязательности.
- Нет ограничения длины текста отзыва на уровне формы/обработчика; `Review.comment` — `TextField` без `max_length`.
- Нет поля публикации и возможности снять отзыв с публикации, сохранив его в базе. Удаление отзыва через админку не является снятием с публикации.
- Нет отдельной Django Form/ModelForm для отзыва; ввод проверяется вручную в представлении.

**Другие реализованные формы:** `TourFilterForm`, `RecommendForm`, `BookingForm`, `ProfileForm` и встроенная `UserCreationForm`. Они демонстрируют работу с формами, но не заменяют недостающие пункты урока.

**Как показать через интерфейс:** в `/admin/tours/review/` создать отзыв, затем открыть соответствующий тур и показать его отображение. Это показывает сохранение и вывод, но обходит проверки `add_review`. Отправку комментария пользователем, ограничение длины и снятие с публикации показать нельзя — этих элементов интерфейса нет. Для демонстрации других форм открыть `/tours/recommend/` и `/bookings/profile/`, ввести неверные значения и показать ошибки после отправки.

## Урок 18: Кастомизация админки

**Статус: выполнено.** Настройки находятся в `tours/admin.py` и `bookings/admin.py`.

**Что сделано:** все собственные модели зарегистрированы. У `TourAdmin` есть `list_display`, `list_filter`, `search_fields`, автоматическое заполнение `slug`, `readonly_fields`, группы `fieldsets` и табличные inline для фотографий и дат. В формах дат и фотографий внутри тура показаны только выбранные поля. У бронирования системные поля, статус, дата, участники и стоимость доступны только для чтения; создание и удаление заявки из админки запрещены. Изменение статуса выполняется действиями подтверждения, отмены и завершения. Есть превью изображений, цветные статусы и счётчики связанных записей.

**Скрытие полей:** учебное поле `Tour.is_featured` не используется на сайте и не включено в `TourAdmin.fieldsets`, поэтому отсутствует в форме администратора. Поле остаётся в базе. Используемое при подборе `preferred_duration_days` включено в форму профиля.

**Только для чтения:** даты создания/обновления, системные поля бронирования, счётчики туров у регионов и категорий, число бронирований в профиле, превью фотографии, итоговая цена и статус наличия мест у даты тура. Вычисляемые значения отображаются и в карточках объектов; на форме создания даты они появляются после сохранения.

**Поиск и фильтры:** поиск настроен для всех девяти собственных моделей, в том числе комментариев по названию тура. Туры фильтруются по активности, региону, категории, сложности и дате создания; комментарии — по публикации, дате и туру; отзывы — по оценке, дате и туру; фотографии — по главному фото и туру; даты туров — по дате и региону; бронирования — по статусу, дате и региону; профили — по дате регистрации и активности пользователя.

**Как показать через интерфейс:** войти суперпользователем в `/admin/`. В разделе туров выполнить поиск, выбрать регион/сложность фильтром и открыть тур: показать группы полей, даты и фото внутри формы, неизменяемые даты создания/обновления. В фотографиях показать превью. В бронированиях выбрать ожидающую заявку и действие подтверждения, затем показать статус и число свободных мест даты. Для успеха нужны будущая дата и достаточное число мест.

## Урок 19: Реализация стандартных задач

**Статус: реализовано в проекте.** Реальная доставка email требует настройки SMTP.

| Задание | Реализация |
| --- | --- |
| Письмо при новом комментарии | После сохранения валидного комментария на сайте `transaction.on_commit()` вызывает `tours/notifications.py`. Получатель — `COMMENT_NOTIFICATION_EMAIL`. При ошибке SMTP комментарий сохраняется, ошибка записывается в журнал. Редактирование и открытие страницы повторных писем не отправляет. |
| Авторизация и регистрация | `UserCreationForm`, автоматический вход после регистрации, стандартные страницы входа/выхода Django и защита личных страниц через `login_required`. |
| Кеширование страниц | Содержимое каталога кешируется шаблонным тегом `cache` на 60 секунд, отдельно для языка и параметров фильтров/страницы. Навигация пользователя, сообщения и CSRF-токены остаются вне кеша. Изменения туров видны после истечения минуты. Карточка с комментариями и доступными местами не кешируется. |
| Два языка | Русский и английский: `LocaleMiddleware`, переключатель в шапке через `set_language`, переводы шаблонов, форм, статусов и сообщений. Каталог переводов — `locale/en/LC_MESSAGES/django.po`, готовый `django.mo` включён в проект. Введённые пользователями названия/описания туров и комментарии остаются на исходном языке. |

**Как показать:** зарегистрироваться через `/accounts/register/`, выйти и войти снова. В шапке выбрать English и нажать кнопку смены языка; проверить каталог, форму комментария и профиль. Оставить комментарий: в консоли `runserver` появится письмо с автором, туром, текстом и ссылкой. Для настоящей почты заполнить SMTP-параметры из `.env.example` и перезапустить сервер. Открыть каталог, изменить название тура в админке и обновить каталог: новое название появится после истечения 60 секунд.

**Проверка:** `tours/test_lesson19.py` проверяет письмо после сохранения, отсутствие письма при ошибках ввода, сбой SMTP, переключение языка, работу и разделение кеша, вход/выход. Тест регистрации есть в `bookings/test_mvp.py`. Команда: `.\.venv\Scripts\python.exe manage.py test --settings=Kyrgyz_Tur.sqlite_settings`.

## Уроки 22–23: Параллеливание процессов; управление запуском, перезапуском и остановкой

**Статус: задание не реализовано в файлах проекта.** В источнике это общая папка уроков 22–23; из-за вложенности её фактический путь заканчивается на `перезапуском/остановкой питон проектов)`. Внутри найдено условие: «Установить и отконфигурировать supervisor для работы со своим проектом».

**Что сделано:** есть WSGI/ASGI-точки входа. Они позволяют запускать Django через сервер приложений, но не являются установкой или настройкой Supervisor. Транзакции бронирования также не заменяют управление процессом приложения.

**Что осталось:** установить Supervisor в среде размещения, создать конфигурацию программы с командой запуска сервера, рабочим каталогом, окружением, пользователем, автозапуском, перезапуском и логами. Проверить запуск, остановку, перезапуск и восстановление процесса. В репозитории конфигурации Supervisor нет; состояние внешнего сервера не проверялось. Отдельное самостоятельное задание для урока 23 из общего условия не выделяется.

**Как показать через интерфейс:** специального экрана Supervisor на сайте нет. После настройки показать `supervisorctl status`, `stop`, `start`, `restart` и логи в терминале сервера, сопоставляя состояние процесса с доступностью сайта в браузере. Сейчас такую демонстрацию провести по проекту нельзя — конфигурация отсутствует.
