# Урок 21: публикация Kyrgyz Tur на Vercel

## Что где работает

- GitHub хранит исходный код.
- Vercel запускает Django и выдаёт публичный HTTPS-адрес.
- Облачный PostgreSQL (например, Neon) хранит пользователей, туры и бронирования.
- Внешнее файловое хранилище нужно для загружаемых фотографий. Локальный каталог
  `media/` не переносится автоматически и не подходит для постоянных загрузок на Vercel.

## 1. Регистрация

Откройте https://vercel.com/signup, выберите Hobby для личного учебного проекта
и вход через GitHub. Используйте аккаунт с репозиторием `Kyrgyz_Tur`.
Если Vercel запросит установку GitHub-приложения, достаточно дать доступ только
к этому репозиторию. Пароль GitHub и коды подтверждения вводите на сайте самостоятельно.

## 2. База данных

Создайте бесплатный PostgreSQL-проект в Neon (https://neon.tech) либо подключите
Neon через Vercel Marketplace. Выберите бесплатный план и сохраните строку подключения
из панели провайдера. Она содержит пароль и не должна попадать в GitHub или скриншоты.

`127.0.0.1` в настройках облачного сайта означает сам облачный сервер, а не ваш ноутбук.
Поэтому локальную базу PostgreSQL сайт на Vercel использовать не сможет.

## 3. Настройки проекта Vercel

Импортируйте GitHub-репозиторий через Add New → Project. Корень проекта — `./`,
framework — Django. Пользовательские Build Command и Output Directory не нужны:
Vercel сам выполняет collectstatic. Версия Python задана в `.python-version`.

Перед развёртыванием задайте Environment Variables:

| Имя | Значение и смысл |
| --- | --- |
| `DJANGO_SECRET_KEY` | Случайная строка длиной не менее 50 символов для подписи данных Django |
| `DATABASE_URL` | PostgreSQL connection URL из Neon; параметры TLS сохраняются |
| `DJANGO_ALLOWED_HOSTS` | Точный домен проекта без `https://`, если он не передан системными переменными Vercel |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | При необходимости дополнительные доверенные адреса форм, с `https://`, через запятую |

Сгенерировать ключ локально:

```powershell
.venv/Scripts/python.exe -c "import secrets; print(secrets.token_urlsafe(64))"
```

Ключ вставляется в настройки Vercel, а не в код. На Vercel DEBUG принудительно выключен,
cookie передаются по HTTPS. Домены из `VERCEL_URL` и `VERCEL_PROJECT_PRODUCTION_URL`
добавляются автоматически; произвольные домены `*.vercel.app` не разрешаются.

Для начала подключайте рабочую базу только к Production. Для Preview нужна отдельная
база/ветка Neon: иначе тестовый деплой сможет менять рабочие данные.

## 4. Создание таблиц

Деплой кода не создаёт таблицы автоматически. Миграции запускаются отдельно и осознанно,
чтобы сборка произвольной preview-ветки не меняла рабочую базу.

Создайте локальный `.env.vercel` с одной строкой `DATABASE_URL=...` для выбранной облачной
базы. Этот файл исключён из Git и загрузки на Vercel. Следующие команды загружают
его только на время выполнения Python-процесса:

```powershell
.venv/Scripts/python.exe -c "from dotenv import load_dotenv; load_dotenv('.env.vercel', override=True); from django.core.management import execute_from_command_line; execute_from_command_line(['manage.py', 'migrate', '--settings=Kyrgyz_Tur.settings'])"
.venv/Scripts/python.exe -c "from dotenv import load_dotenv; load_dotenv('.env.vercel', override=True); from django.core.management import execute_from_command_line; execute_from_command_line(['manage.py', 'createsuperuser', '--settings=Kyrgyz_Tur.settings'])"
```

Убедитесь, что файл действительно содержит DATABASE_URL: при его отсутствии настройки
используют локальный PostgreSQL. Эти команды создают новую схему и администратора;
существующие локальные туры и фотографии сами не переносятся. Перенос данных выполняется
отдельно после проверки назначения базы. Для учебной пустой базы можно запустить seed_demo
тем же способом вместо migrate.

## 5. Проверка публикации

После Deploy дождитесь статуса Ready. Проверьте главную, каталог, регистрацию и вход,
отправку форм, `/admin/` и её оформление. Проверьте сохранение бронирования после
повторного открытия сайта. Ошибки запуска смотрите в Runtime Logs, ошибки установки
зависимостей — в Build Logs. Публичный URL записывайте в отчёт только после проверки.

Публикация ещё не завершена, пока не настроены база и требуемые загрузки фотографий.
Отправка реальных email также требует SMTP-параметров; консольный backend только пишет
письмо в журнал. Локальный кеш Vercel не является общим кешем всех экземпляров.

## Уроки 22–23

Условие требует установить и настроить Supervisor, показать запуск, остановку,
перезапуск и восстановление процесса. Обычный Django-деплой на Vercel управляется
платформой и не предоставляет такой демонстрации. Для этих уроков нужен отдельный
Linux-сервер или локальная Linux-среда (например, Docker/WSL). Они не считаются
выполненными самим фактом публикации на Vercel.

Документация: https://vercel.com/docs/frameworks/full-stack/django
